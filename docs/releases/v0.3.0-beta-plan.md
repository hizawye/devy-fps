# v0.3.0-beta Plan

## Objective
- Convert the shipped alpha baseline (`v0.2.0-alpha`) into a beta-ready implementation stream with explicit scope, quality gates, and release criteria.
- Keep protocol compatibility stable while expanding gameplay depth, UX clarity, and operational confidence.

## Fixed Defaults for Beta
- Version target: `v0.3.0-beta`.
- Protocol compatibility: keep protocol window at v1 (`kMinSupportedProtocolVersion == 1`, `kMaxSupportedProtocolVersion == 1`) for beta.
- Deployment model: single authoritative server process (no sharding work in this milestone).
- Release evidence source: continue using scripts and artifact layout under `artifacts/releases/`.
- Workspace hygiene policy: `.worktrees/` is local-only and must remain untracked; never include it in release/docs commits. If needed, add it to local excludes via `.git/info/exclude`.

## Milestone Tracks

1. B1.1 Weapon and damage balancing pass

## Mandatory Beta Quality Gates

- `scripts/configure.sh debug-vcpkg`
- `scripts/build.sh debug-vcpkg`
- `scripts/test.sh debug-vcpkg`

2. Release operations subset
- `ctest --preset debug-vcpkg -R '^server\\.release\\.' --output-on-failure`

3. Acceptance pack
- `scripts/alpha-acceptance-pack.sh config/server_test.json artifacts/releases/beta-acceptance/candidate debug-vcpkg 8 8 1`

4. Reliability drills
- `ctest --preset debug-vcpkg -R '^server\\.reliability\\.' --output-on-failure`
